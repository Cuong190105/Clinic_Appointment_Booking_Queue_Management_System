# Layout patterns

## A. Title / narrative opener

Large title and subtitle occupy the left 60%; on the right, three small editable service nodes form a restrained flow motif. Use a dark navy title field only on slide 1 to create a distinct opening.

## B. Role journey

Four role cards across the upper two-thirds connect to a four-stage clinic journey along the bottom. Role labels are secondary to actions.

## C. Legacy or target architecture

Use a left-to-right flow with a single database anchor. Group internal layers inside a service boundary. A concise tradeoff callout explains why the model worked and what constrained change.

## D. Conceptual ERD

Use four color-coded domain clusters, only the entities and links named in the project report. Prefer relationship labels and clear grouping over reproducing every table. Explicitly label it conceptual.

## E. Ownership map

Place the Gateway above or left of service cards. Each card has service name, ownership noun phrases, and a small database icon/label. Avoid duplicating all responsibilities from the speaker notes.

## F. Event and orchestration flow

For the booking SAGA, use numbered stages and distinguish synchronous request/response from event delivery. For Queue choreography, show event fan-out and consumer ownership. Avoid crossing arrows where a short labeled connector is clearer.

## G. Target scorecard

Show four or five thresholds as large figures with compact labels. Distinguish latency thresholds from invariants. Mark values as project targets, not production promises.

## H. Benchmark results

Slide 14 uses a 3-row, 3-column compact layout; provide profile, load, and key outcome, with caveat callout below. Slide 15 uses a native grouped bar chart on the left and a two-row comparison table on the right. A single footer caveat describes run counts and database state.

## I. Timeline

One horizontal timeline with 4–5 milestones. Use exact values and short run descriptors; do not imply measurements from different workloads form a controlled series.

## J. Conclusion / references

Conclusion uses three blocks with verbs: built, measured, next. References use two columns, 14–16 pt, concise citation labels and file names. The appendix reference slide is not timed.
